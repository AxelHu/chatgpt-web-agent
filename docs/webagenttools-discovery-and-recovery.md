## 发现与调用

1. **已有定义就直接调用。** 以本轮实际提供的工具名和参数为准，不重复加载。
2. **缺少定义时按需发现。** 使用本轮可用的发现入口，按任务筛选工具；发现后按返回的真实定义调用。
3. **用任务本身核验。** 需要读文件就读取相关文件，需要执行命令就用相关的最小命令；发现成功不等于执行成功，读取成功也不等于写入成功。
4. **按真实回执衔接后台任务。** 执行返回运行状态和会话 ID 后，再用当前提供的进程工具查询该会话。

两种发现入口的使用条件如下；不能从旧文档推断本轮一定提供哪一种：

| 本轮提供的入口 | 使用方法 |
|---|---|
| `api_tool.list_resources` | 按当前定义发现 WebAgentTools。下方是 2026-09-21 使用过的参数示例。 |
| Code Mode、`ALL_TOOLS` 和 `tools` | 在注册表中按 WebAgentTools 与所需能力筛选，读取返回定义后调用。不要写死历史命名空间。 |

历史 `api_tool` 参数示例；仅在本轮定义仍支持这些参数时使用：

```json
{"paths":["WebAgentTools"],"query":"exec"}
```

一个入口未找到工具时，检查本轮是否另有可用入口；缺少某个包装层不能推出整个工具集失效。
工具定义已经齐全时，无需为了验证而重复发现。

## 根据回执定位故障

| 实际观测 | 下一步 |
|---|---|
| 尚未加载定义 | 先发现所需工具，再核验调用。 |
| 调用入口报 `Resource not found` | 检查工具资源绑定；若回执明确指向具体文件，则检查该文件路径。 |
| 审核拦截或权限拒绝 | 保留原始请求与回执，按规范正文的“故障恢复”处理；不能据此认定本机工具失效。 |
| 超时、传输或会话错误 | 判断故障所在层次；写入结果不明时先核对实际状态。 |
| 本地命令返回非零退出码和具体错误 | 先修正命令或对应的本地问题。 |
| 云端 `/mnt/data` 等临时文件丢失 | 检查该云端文件的状态，与本机工具是否可用分别判断。 |
| 读取成功、执行失败 | 分别记录两次调用的结果，不扩大为整个工具集的结论。 |

重试次数、审核复核和写入状态核验统一按规范正文的“故障恢复”执行，本页不另设一套规则。
暂时受阻时保留成果，继续独立工作；有新进展或再次需要时，再发现和核验。
避免高频轮询、刷新或重启。后续仍需该能力时，根据新的调用结果更新判断。
